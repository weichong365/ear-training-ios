1把代码推送到 GitHub

代码目前只在你本机，需要先传到 GitHub（Codemagic 支持的托管平台）。

1.1 注册 / 登录 GitHub

  1. 打开 github.com，注册一个账号（已有就登录）。

1.2 新建一个私有仓库

  1. 右上角 + → New repository。
  2. 仓库名随便填，例如 lianerdazi-ios。
  3. 选 Private（私有），不要勾选「Add README / .gitignore」。
  4. 点 Create repository。

1.3 推送代码（在 Windows 的 Git Bash 里执行）

把下面命令里的 你的用户名 和 仓库名 替换成你实际的值，然后整段复制到 Git Bash 执行：

cd "F:\WorkBuddy\练耳大师\ios-app"
git add app.json codemagic.yaml
git commit -m "feat: 接入 Codemagic 免费 CI 构建 iOS"
git remote add origin https://github.com/你的用户名/仓库名.git
git push -u origin master
如果提示 remote origin already exists，说明之前加过远程，改成 git remote set-url origin https://github.com/你的用户名/仓库名.git 再 push。
推送时如果要求输入用户名密码：GitHub 现在不支持密码推送，需要「Personal Access Token」。遇到这个提示再来找我，我给你完整的 token 创建步骤。

2新建 App Store Connect API Key

给 Codemagic 一个「签名 + 上传」的凭证（你的开发者账号 6806168169）。

  1. 登录 appstoreconnect.apple.com。
  2. 左侧 Users and Access（用户和访问） → Integrations（集成） → App Store Connect API。
  3. 点 + 新建一个 Key，名称填 codemagic，权限选 App Manager。
  4. 点 Generate → 立刻 Download API Key 下载 .p8 文件。
⚠️ .p8 文件只能下载这一次！下载后务必存好，弄丢了只能删掉重新建一个 Key。

记下两个值（后面第 3 步要用）：

  • Issuer ID：页面表格上方的字符串。
  • Key ID：表格里刚生成那行的 ID（形如 XXXXXXXXXX）。

3Codemagic 连接仓库并构建

登录 Codemagic，连上 GitHub 仓库，填入上一步的密钥。

3.1 注册并连接 GitHub

  1. 打开 codemagic.io，点 Sign in with GitHub（用第 1 步的 GitHub 账号登录）。
  2. 登录后点 Add application，选 GitHub，授权后从列表里选中你刚推的仓库。
  3. 项目类型选 React Native，点 Finish: Add application。

3.2 配置 API Key（关键：名称必须一字不差）

  1. 左侧 Teams → Team integrations → Developer Portal → Manage keys。
  2. 点 Add key，按下面填：
字段填什么
API key namelianerdazi-asc-key（必须一字不差，和 codemagic.yaml 对应）
Issuer ID第 2 步记下的 Issuer ID
Key ID第 2 步记下的 Key ID
.p8 文件上传第 2 步下载的 .p8
  1. 点 Save。

3.3 触发构建

  1. 回到应用页，点 Start new build。
  2. 分支选 master，workflow 选 ios-build。
  3. 点 Start build。
构建会在 macOS M2 机器上跑：装依赖 → 生成 iOS 工程 → 自动签名 → 打包 .ipa → 自动上传 App Store Connect。全程约 15–30 分钟。

4构建成功后：提交审核

  1. 等 Codemagic 显示构建成功（绿色 ✓），说明 .ipa 已自动上传到 App Store Connect。
  2. 打开 appstoreconnect.apple.com → 你的 App「练耳搭子-音乐艺考听音训练」。
  3. 在 TestFlight / 构建 里能看到新上传的构建（版本 1.0.0，build 40）。
  4. 回到之前那本「后台操作手册」，把截图、元数据、隐私标签补齐。
  5. 选刚上传的构建 → 点 提交审核。

!常见问题 & 后续维护

首次构建失败了怎么办？

把 Codemagic 里的报错日志截图发我，我帮你定位（常见是 Xcode 版本 / pod 下载超时 / 密钥名称不匹配）。

以后每次发新版本

  • 改完代码，提交并 git push，然后到 Codemagic 再点一次构建即可。
  • 版本号：每次上传 App Store 的 build 号必须递增。当前是 app.json 里的 ios.buildNumber = "40"，下次发版前把它改成 41、42… 再提交。
