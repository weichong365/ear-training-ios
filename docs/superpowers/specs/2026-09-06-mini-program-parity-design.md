# 小程序优化同步至 iOS App 设计规格

## 目标

以当前小程序源码为训练产品行为标准，将训练、界面、题库、音频、答题与批改优化同步到 Expo/React Native iOS App。保留 iOS 的 Apple 订阅与本地数据实现，不引入微信邀请、微信云开发或微信支付能力。

## 产品边界

### 本轮同步

- 首页训练入口、省份上下文与训练数据概览。
- 省份选择、专项训练、模拟考试、错题本、练习统计的界面与交互状态。
- 单音、音组、音程、和弦、节奏、旋律及和声音程连接的出题规则。
- 标准音、题目音、播放次数、播放互斥、前后台切换与答案回放。
- 五线谱写入、固定答题分区、纵向叠写、拖动、临时记号、擦除与时值输入。
- 答案完整性、判分、正确答案展示、红笔批改标记、错题强化与统计记录。

### 明确保留

- `src/services/subscription.tsx` 的 Apple 订阅与权限判断。
- iOS 本地存储和已有 App Store 合规页面。
- Expo Router、React Native、expo-audio 与现有依赖集合。

### 明确排除

- 小程序邀请好友增加使用天数。
- 微信云函数、微信用户身份、微信云端同步与微信支付。
- 与训练一致性无关的重构、新依赖或视觉功能。

## 同步原则

1. 小程序是产品规则的来源，iOS 保持平台原生实现；不得直接移植 `wx.*` API 或 WXML/WXSS。
2. 题目数据必须只有一个事实来源：生成结果中的 MIDI、拼写、时值、拍号与调号同时驱动音频、谱面、文本答案和判分。
3. 公共规则优先同步到 `src/core/legacy/` 与 `src/core/`，页面只消费规则，不复制判分算法。
4. 已有未提交修改逐项核对后保留；不覆盖用户文件或 `app-store-pages/`。
5. 不新增依赖；优先复用现有 `AnswerStaff`、`NotationEditor`、`audio-engine`、`exam-answer` 与主题组件。

## 核心题库规则

- 所有基础音高题保持 G3–A5 的已采样范围。
- 专项单音每 10 题包含 1–2 个变化音且题内不重复；模拟考试 5 个单音恰好 1 个变化音。
- 三、四、五音组按顺序作答，组内不重复，相邻音不超过六度，每组最多 1 个变化音且变化音出现概率为 25%。
- 音程覆盖一至八度内既定种类，并区分旋律音程的顺序判分与和声音程的无序叠写判分。
- 三和弦专项统一覆盖大、小、增、减三和弦；10 题转位分布为原位 5、第一转位 3、第二转位 2；增减和弦总体概率约 30%。
- 旋律调号限定 C 大调、G 大调、F 大调；节奏与旋律继续使用省份框架指定的拍号、难度和播放次数。
- 省份已有专属框架时采用对应年份规则，未录入省份明确回退全国通用框架。

## 答题与批改

- 未成功启动题目播放前不允许写入答案。
- 播放过程中禁止重复启动；达到考试规定次数后禁止继续播放，交卷或提交后答案回放不限次数。
- 单音、音组、音程和和弦的答题音符默认使用全音符。
- 单音使用一个固定区域；音组和旋律音程按顺序使用独立区域；和声音程与和弦在同一区域纵向叠写。
- 音符支持上下拖动、临时升降还原记号及双击擦除；修改后实时更新答案完整性。
- 旋律音程按顺序比较，和声音程与和弦按音高集合比较；和弦性质与转位仅在题目明确要求时参与完整性和判分。
- 节奏与旋律按小节、拍号、调号、时值、休止及音高逐项比较，禁止超出小节容量。
- 错题反馈保留考生红色答案，并以安全水平间距叠加绿色正确答案；节奏和旋律在原谱下方显示标准答案。
- 文本答案必须由与谱面、音频相同的数据生成，不维护第二套音名映射。

## 音频行为

- 除节奏题外，播放序列先使用 A4 标准音，再按规定间隔播放正题。
- 旋律音程、音组和旋律按顺序播放；和声音程、和弦与连接题按题目结构播放。
- 页面离开或 App 进入后台时停止当前播放并清理状态；回到前台后允许重新触发，不自动叠加播放。
- iOS 继续使用现有本地采样与 `expo-audio`，仅同步调度语义，不复制小程序的文件系统 WAV 缓存实现。
- 每个生成题目的所有 MIDI 必须落在现有采样范围，且自动校验采样文件与目标频率。

## 界面与状态

- 首页保持墨绿与米白视觉系统，省份入口清晰展示当前省份；训练入口采用紧凑双列布局，不恢复难度选择。
- 训练页区分准备、作答、反馈、完成四个状态；按钮禁用、播放提示、进度和底部操作随状态一致变化。
- 模拟考试保持电子卷面和单列小题；各小题播放计数读取省份框架，不写死次数。
- 错题本与统计页补齐加载、失败重试、空状态和页面卸载后的异步结果保护。
- 使用现有矢量图标与主题常量，不使用系统 Emoji 充当功能图标。
- 保持 VoiceOver 标签、44pt 以上点击区域和禁用状态说明。

## 数据与兼容性

- 新生成记录使用当前完整题目结构保存，确保错题可重新进入同题强化。
- 读取旧记录时继续兼容缺少拼写、转位或时值字段的历史数据；无法可靠重练的记录仍可查看，但不进入错误的训练流程。
- 本轮不改变订阅数据格式，不上传或迁移微信云端数据。

## 验证标准

- 将小程序 `core`、`province-frameworks`、`practice-flow`、`practice-staff`、`exam-flow`、`audio-scheduling` 和 `ui-system` 中适用于 iOS 的产品断言移植为最小可运行检查。
- 每项行为修改先增加失败检查，再做最小实现，并运行 TypeScript、ESLint、核心、答案、本地存储、省份与采样验证。
- 对单音、旋律音程、和声音程、和弦、节奏、旋律和连接题分别完成一次端到端状态检查。
- 因当前 Windows 环境没有 Xcode，自动代码与逻辑验证可本地完成；最终 iOS 布局、音频与触控验收需使用 TestFlight 真机或已连接的 Mac 模拟器。

## 完成定义

当相同省份、题型和生成数据输入时，iOS 与小程序在题目结构、播放语义、作答要求、判分结果、正确答案和错题处理上保持一致；界面信息架构与状态反馈一致，同时 Apple 订阅流程及 iOS 本地数据保持可用。
